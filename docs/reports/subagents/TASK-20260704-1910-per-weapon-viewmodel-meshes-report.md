# Subagent Report — Per-Weapon Viewmodel Meshes

## Task

Wire each weapon index to its correct compiled viewmodel mesh path so the player sees the actual gun model (AR-15, shotgun, rocket launcher) instead of a generic arms mesh.

## Status

Verified already-implemented on main; validated and promoted to review.

## Scope

**In bounds:**
- Map each weapon index to its correct compiled viewmodel mesh path.
- Verify the mesh files exist and are loadable.
- Keep the arms mesh as a fallback for unknown weapon indices.
- Preserve the weapon presentation layer seam.

**Out of bounds:**
- No new mesh authoring or asset creation.
- No hand/arm IK or animations.
- No weapon balance changes.
- No reload animation.

## Findings

The per-weapon mesh path wiring was already committed to `main` in commit `8b89a5d4`. The function `weapon_viewmodel_mesh_path()` in `client/include/ahamkara/client/weapon_viewmodel_data.h` already returns per-weapon paths:

| Index | Weapon          | Mesh Path                                      |
|-------|-----------------|------------------------------------------------|
| 0     | AR-15           | `assets/compiled/models/viewmodel_ar15.aemesh` |
| 1     | Shotgun         | `assets/compiled/models/viewmodel_shotgun.aemesh` |
| 2     | Rocket Launcher | `assets/compiled/models/viewmodel_rocket_launcher.aemesh` |
| any   | Fallback        | `assets/compiled/models/viewmodel_arms.aemesh` |

### Compiled Assets Verified

The following compiled `.aemesh` files exist in `assets/compiled/models/`:
- `viewmodel_ar15.aemesh`
- `viewmodel_shotgun.aemesh`
- `viewmodel_rocket_launcher.aemesh`
- `viewmodel_arms.aemesh`
- `viewmodel_pistol.aemesh` (not yet wired to a weapon index)
- `viewmodel_rifle.aemesh` (not yet wired to a weapon index)

### Blender Source Mesh Names Verified

The per-weapon mesh names match the `output_name` fields in `tools/blender/weapons/meshes/*.json`:
- `ar15.json` → `output_name: "viewmodel_ar15"`
- `shotgun.json` → `output_name: "viewmodel_shotgun"`
- `rocket_launcher.json` → `output_name: "viewmodel_rocket_launcher"`

These match the `mesh` field in `tools/blender/weapons/archetypes.json`.

### Weapon Count

`kWeaponViewmodelCount` is correctly set to 3, matching the three weapons (AR-15, Shotgun, Rocket Launcher) that have per-weapon transforms, grip sockets, reload data, ADS transforms, and now mesh paths defined. No change needed.

### Presentation Layer Seam Preserved

The mesh path resolution stays entirely in the client presentation layer (`client/include/ahamkara/client/weapon_viewmodel_data.h`). The `weapon_presentation.cpp` consumer calls `weapon_viewmodel_mesh_path(weapon_index)` to load meshes via `GpuModelCache`. No gameplay or `WeaponRuntime` code references mesh paths.
