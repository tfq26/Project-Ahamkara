# Design documents

Design documents explain a proposed or accepted mechanism before it becomes
ordinary subsystem truth. Every design must declare its status, constraints,
ownership, rollout, and validation bar.

- [Extensible error identity and handling](error-system.md) — **Proposed**.

Once a design is fully implemented, move stable behavior into the relevant
[`../systems/`](../systems/README.md) document and retain only the decision and
compatibility contract here. Execution status belongs in
[GitHub Issues](https://github.com/tfq26/Project-Ahamkara/issues).
