# Team Protocol

## Minimum Start-of-Run Declaration

Before substantial work, the agent should internally or explicitly define:

- scope
- likely files
- main risk
- validation plan

## Minimum End-of-Run Declaration

Before stopping, the agent should be able to state:

- implemented behavior
- validation run
- unresolved risk
- next recommended step

## Healthy Team Patterns

- small, well-scoped changes
- honest intermediate states
- clear ownership boundaries
- readable handoffs
- named dependencies

## Unhealthy Team Patterns

- claiming completion from compile success alone
- silently editing shared files across another agent’s scope
- reporting “done” when runtime verification was skipped
- hiding blockers inside optimistic prose
